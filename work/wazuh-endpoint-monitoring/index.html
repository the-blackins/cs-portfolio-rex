Monitoring an endpoint with Wazuh.

00 / OVERVIEW

What the lab set out to do

The goal was to connect an endpoint to Wazuh, monitor file changes, and use VirusTotal information to support an investigation of a test file.

The exercise also covered vulnerability-detection concepts and configuration. The environment was a virtual lab, and the documented screenshots capture selected points in the setup and test.

01 / IMPLEMENTATION

Getting the endpoint connected

I deployed Wazuh in the virtual environment and installed a Windows agent. The project screenshots show installation and service-start steps, followed by a dashboard listing the Windows endpoint as active.

That dashboard establishes connectivity for one endpoint at the time of capture. It does not represent an ongoing fleet, production deployment, or measured availability.

02 / INVESTIGATION WORKFLOW

Monitoring and file context

File integrity monitoring

I configured file integrity monitoring (FIM) and documented a dummy-file exercise in the Windows System32 directory. My notes describe a file-addition alert and the details reviewed. The matching Wazuh event screenshot was not included in the supplied presentation.

VirusTotal integration

I configured the integration for syscheck events and documented an EICAR test-file exercise. The supplied screenshot shows a VirusTotal report identifying the test file. My project notes report FIM and VirusTotal alerts, although the Wazuh alert captures are unavailable.

EVIDENCE DISTINCTION

The VirusTotal report shows a test-file result. It is not a screenshot of the Wazuh alert pipeline, and the vendor detections in that report are not a count of incidents I handled.

Vulnerability review

The project discussed CVE identifiers, CVSS severity, vulnerability information, and scan settings. My résumé records vulnerability-scanning and active-response configuration work. The supplied images do not show a completed vulnerability inventory or an executed response action.
